# 演示样例说明

这两个样例用于一键演示、人工核对和自动化测试。**所有图片都是程序生成的合成图像，
不是实拍照片**，由 [`build_examples.py`](build_examples.py) 使用固定随机种子渲染。

## 共同参数

- 图解：32 行 × 12 针，双色平针提花，深绿色与米白色（BGR：`(74,104,78)` 与 `(235,232,222)`）
- 照片中可见完整行数：5 行
- 图解 PNG 带 26 px 外边距和 2 px 灰色网格线，选区为网格外边界
- 照片带针织纹理、织针在上、轻微透视、光照渐变、噪声和暗角

## case1_unique —— 唯一位置

| 项目 | 内容 |
|---|---|
| 随机种子 | 20261121 |
| 照片实际覆盖 | 图解第 19–23 行，最近完成第 23 行 |
| 预期状态 | 唯一候选 |
| 预期窗口 | 第 19–23 行 |
| 最近完成 / 下一行 | 23 / 24 |
| 特殊性质 | 5 行观测窗口在整张图解中唯一；把两种颜色整体交换后也没有其他等价窗口 |
| 附加变体 | `photo_blurred.png`（模糊）、`photo_lowcontrast.png`（低对比度） |

`photo_blurred.png` 会触发“照片偏模糊”的质量提示并整体降权；
`photo_lowcontrast.png` 的两种颜色 Lab 色差只有约 12，所有格子权重被置 0，
匹配结果为「证据不足」。

## case2_repeat —— 重复花纹

| 项目 | 内容 |
|---|---|
| 随机种子 | 20261122 |
| 基本周期 | 8 行（已校验不存在 1/2/4 行的更小周期） |
| 照片实际覆盖 | 第 20–24 行，最近完成第 24 行（**只有素材生成器知道，算法看不到**） |
| 预期状态 | 多个候选 |
| 预期窗口 | 第 4–8、12–16、20–24、28–32 行 |
| 预期最近完成行 | 8、16、24、32 |
| 限定 20–26 后 | 唯一候选：第 20–24 行，最近完成 24，下一行 25 |

由于每 8 行重复，5 行窗口会在每个周期的相同位置出现，因此第 4–8、12–16、20–24、28–32
行都解释得通。这正是应用要暴露的歧义：它不会假装知道真实进度，而是保留全部候选，
并提示补拍更早的行或限定范围。

## 文件清单

每个案例目录包含：

| 文件 | 用途 |
|---|---|
| `chart.png` | 带外边距和网格线的配色图解 |
| `photo.png` | 合成织片正面照（含纹理/透视/噪声） |
| `chart_grid.csv` | 图解矩阵，行号从 32 递减到 1（人眼阅读顺序） |
| `observation_labels.csv` | 观测矩阵，本地第 1 行 = 照片顶行（最新完成行） |
| `observation_weights.csv` | 观测逐格权重（0–1） |
| `matrices.txt` | 图解/观测/权重的字符画版本，便于人工逐格核对 |
| `case.json` | 输入参数：选区、四角、行列数、真实停织行、素材说明 |
| `expected.json` | 独立保存的预期答案与范围场景 |
| `photo_blurred.png` / `photo_lowcontrast.png` | 仅 case1：质量处理演示 |

## 人工核对方法

打开 `matrices.txt`：

- `#` 代表深色（标签 0），`.` 代表浅色（标签 1）。
- 图解部分顶部是第 32 行，底部是第 1 行。
- 观测部分顶部是照片顶行（最新完成行），底部是照片底行。
- case1 中，把观测矩阵自上而下与图解第 23、22、21、20、19 行对照，应逐格一致。
- case2 中，同一观测还能与第 8、16、32 行结束的窗口逐格一致。

`expected.json` 中的 `scenarios` 保存了“限定最近完成行 20–26”后的预期，
`min_best_score`/`max_diff_cells` 给出允许的分数与差异格上限。

## 重新生成

```powershell
python examples\build_examples.py
```

脚本会重新写出两个案例的图片、CSV、`matrices.txt`、`case.json`、`expected.json`，
并立即用 `core.pipeline.locate` 回读验证；如果与预期不符会直接抛出 AssertionError。
生成过程完全确定：同样的种子与库版本得到逐字节相同的 PNG（OpenCV 版本不同时
渲染细节可能有微小差异，但矩阵和预期答案不变）。
